** Pin built-ins straight shouldn't reinstall
Some MELPA packages declare a dependency on a library that already ships
built into Emacs (e.g. ~project~, required by ~flymake-ruff~). Straight
doesn't know that and happily clones+builds a *second*, separate copy from
GNU ELPA, whose build directory then gets prepended to =load-path=. The
next time anything does ~(require 'project)~ after the built-in version has
already been loaded once, Emacs throws:
"Feature 'project' loaded from A is now provided by B" -- which aborts
whatever hook/mode-init triggered it (this is what silently broke
python-ts-mode's tree-sitter fontification AND eglot/flymake startup: the
error happened mid-way through ~python-base-mode-hook~, so hooks queued
after the failure point, like ~eglot-ensure~ and ~flymake-ruff-load~, never
ran).

Telling straight these are ~:type built-in~ up front stops it from ever
trying to fetch a separate copy.
#+BEGIN_SRC emacs-lisp
  (straight-use-package '(project :type built-in))
#+END_SRC

* Backspace Key
Set ctrl+h as backspace and ctrl+? as emacs-help
#+BEGIN_SRC emacs-lisp
(defun delete-word (arg)
  "Delete characters forward until encountering the end of a word.
  With argument, do this that many times."
  (interactive "p")
  (if (use-region-p)
	  (delete-region (region-beginning) (region-end))
    (delete-region (point) (progn (forward-word arg) (point)))))

(defun backward-delete-word (arg)
  "Delete characters backward until encountering the end of a word.
  With argument, do this that many times."
  (interactive "p")
  (delete-word (- arg)))

(global-set-key (kbd "C-?") 'help-command)
(global-set-key (kbd "M-?") 'mark-paragraph)
(global-set-key (kbd "C-h") 'delete-backward-char)
(global-set-key (kbd "M-h") 'backward-delete-word)

#+END_SRC
